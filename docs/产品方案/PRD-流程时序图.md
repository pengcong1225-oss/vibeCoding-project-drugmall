### 2.2 阶段说明

#### 阶段一：选购药品与提交问诊（步骤1-5）

**用户操作**：
1. 用户浏览药品详情，选择需要购买的药品
2. 如为处方药，系统提示需要问诊开方
3. 用户提交问诊申请，选择就诊人并描述症状

**系统处理**：
4. 后端API创建问诊单，记录问诊信息
5. 系统将问诊请求推送给匹配的在线医生

#### 阶段二：医生接诊与开方（步骤6-10）

**医生操作**：
6. 医生接诊，查看患者症状描述
7. 通过IM与用户进行在线问诊沟通
8. 根据问诊结果开具电子处方

**系统处理**：
9. 系统生成电子处方，记录处方信息
10. 通知用户处方已开具，可进行购药

#### 阶段三：订单创建与支付（步骤11-18）

**用户操作**：
11. 用户选择使用处方购药，进入支付流程
12. 确认订单信息，选择配送方式（快递/自取）

**系统处理**：
13. 锁定对应门店或仓库的药品库存
14. 拉起支付页面，等待用户完成支付
15. 用户完成支付，支付网关返回支付结果
16. 系统处理支付回调，更新订单状态
17. 扣减实际库存，生成出库单
18. 确认出库，准备发货

**用户通知**：
19. 系统通知用户订单已支付成功，发货/取药待办

## 3. 到店取药时序图

### 3.1 完整时序图


### 3.2 阶段说明

#### 阶段一：门店选择与订单创建（步骤1-7）

**医生操作**：
1. 医生完成问诊后开具电子处方

**用户操作**：
2. 用户选择"到店自取"配送方式
3. 系统查询附近可用门店列表及库存情况
4. 用户选择合适的取药门店
5. 确认门店后，系统创建到店自取订单

**系统处理**：
6. 创建订单记录
7. 锁定对应门店的药品库存

#### 阶段二：支付处理（步骤8-14）

**用户操作**：
8. 用户进入支付流程，确认订单信息
9. 系统拉起支付页面
10. 用户完成支付

**系统处理**：
11. 处理支付回调，更新订单状态为"已支付"
12. 扣减门店实际库存
13. 确认库存扣减成功
14. 通知用户支付成功

#### 阶段三：取药码生成（步骤15-17）

**系统处理**：
15. 生成唯一取药码（包含二维码和数字码）
16. 确认取药码生成成功
17. 向用户展示取药码，同时发送短信通知

#### 阶段四：到店取药（步骤18-24）

**用户操作**：
18. 用户凭取药码到指定门店取药

**门店操作**：
19. 门店工作人员扫描用户展示的取药码
20. 系统确认取药码有效且未使用过
21. 门店发放药品给用户
22. 确认用户已取走药品

**系统处理**：
23. 通知用户取药已完成
24. 更新订单状态为"已完成"，业务流程结束

## 5. 时序图说明

### 5.1 图例说明

| 符号 | 含义 | 说明 |
|------|------|------|
| `│` | 生命线 | 表示对象的生命周期 |
| `│--->` | 同步消息 | 发送同步请求，等待响应 |
| `│---->` | 异步消息 | 发送异步请求，不等待响应 |
| `<----` | 返回消息 | 返回响应结果 |
| `<--->` | 双向通信 | 双向持续通信（如IM对话） |
| `│----│` | 激活条 | 表示对象正在执行操作 |

### 5.2 参与者说明

| 参与者 | 角色 | 职责 |
|--------|------|------|
| 用户 | 患者 | 发起购药请求，完成支付，到店取药 |
| 前端APP | 客户端 | 展示界面，收集用户输入，调用后端API |
| 后端API | 服务端 | 处理业务逻辑，数据存储，协调各服务 |
| AI引擎 | 智能服务 | 提供AI预问诊、症状分析等智能能力 |
| 医生端 | 医生工作台 | 医生接诊、开方、问诊沟通 |
| 支付网关 | 支付服务 | 处理支付请求，完成资金结算 |
| 药店系统 | 门店系统 | 库存管理、取药码核销、药品发放 |

## 6. 关键流程节点说明

### 6.1 处方状态流转

```
医生开方 -> 处方生效 -> 处方使用 -> 处方完成
    |          |          |
    └----------┴----------┘
              |
              处方过期
```

**状态说明**：
- **待生效**：医生已开方，系统正在处理
- **已生效**：处方正式生效，可用于购药
- **已使用**：处方已被用于购药，不可再次使用
- **已过期**：超过有效期，处方自动失效

### 6.2 订单状态流转

```
创建订单 -> 待支付 -> 已支付 -> 待发货 -> 已发货 -> 已完成
    |        |         |         |         |
    └--------┴---------┴---------┴---------┘
              |
              订单取消
```

**关键节点**：
- **待支付**：订单创建成功，等待用户支付
- **已支付**：支付成功，准备发货/取药
- **已完成**：用户确认收货或取药完成

### 6.3 库存状态流转

```
可用库存 -> 锁定库存 -> 扣减库存 -> 完成出库
    |          |          |
    └----------┴----------┘
              |
              释放库存
```

**锁定机制**：
- **订单创建**：锁定对应数量的库存
- **支付超时**：自动释放锁定的库存
- **支付成功**：锁定转为实际扣减
- **订单取消**：释放锁定的库存
