## 1. 在线处方购药流程（已知药品）

### 1.1 流程概览

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 选购药品 │ -> │ 提交问诊 │ -> │ 医生接诊 │ -> │ 医生开方 │ -> │ 患者支付 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

### 1.2 详细步骤说明

#### 步骤1：选购药品（预计1-3分钟）
**用户操作**：
1. 打开DrugMall首页或分类页
2. 通过以下方式查找药品：
   - 搜索栏输入药品名称或症状关键词
   - 点击分类导航浏览药品类别
   - 使用扫码功能扫描药品条形码
3. 点击药品进入详情页面
4. 查看药品信息：
   - 药品名称、规格、生产厂家
   - 适应症、用法用量、不良反应
   - 价格、库存状态、配送方式
5. 选择购买数量，点击"加入购物车"
6. 系统判断药品类型：
   - **非处方药（OTC）**：可直接进入购物车结算
   - **处方药（Rx）**：提示"处方药需凭处方购买，请先问诊"

**系统处理**：
- 记录用户浏览行为，用于个性化推荐
- 检查药品库存状态
- 识别处方/非处方药类型
- 更新购物车数据

**异常处理**：
- 药品库存不足：提示"库存不足，建议选择其他门店或等待补货"
- 药品下架：提示"该药品已下架，推荐相似药品"
- 网络异常：提示"网络连接失败，请检查网络后重试"

---

#### 步骤2：提交问诊（预计2-5分钟）
**用户操作**：
1. 系统提示"该药品为处方药，需先问诊开方"
2. 用户点击"去问诊"按钮
3. 进入问诊页面，系统显示：
   - 已选药品信息（名称、规格、数量）
   - 需要选择的就诊人
4. 选择就诊人：
   - 从已添加的就诊人列表中选择
   - 或点击"添加就诊人"新建
5. 填写问诊信息：
   - 主要症状（多选）：头痛、发热、咳嗽、咽痛等
   - 症状描述（文字输入）：详细描述病情
   - 发病时间：今天/昨天/前几天
   - 既往病史：是否有慢性病、过敏史
   - 用药史：近期是否服用过其他药物
   - 上传图片（可选）：检查报告、症状照片等
6. 选择科室（可选）：
   - 系统根据症状智能推荐科室
   - 用户可手动选择或接受推荐
7. 选择医生（可选）：
   - 系统推荐在线医生
   - 用户可选择指定医生或接受系统分配
8. 确认提交问诊

**系统处理**：
- 验证就诊人信息完整性
- 分析症状描述，提取关键信息
- 智能匹配推荐科室和医生
- 计算预计等待时间
- 创建问诊记录，状态设为"待接诊"
- 发送通知给匹配的医生

**异常处理**：
- 就诊人信息不完整：提示"请完善就诊人信息"
- 症状描述为空：提示"请描述您的症状，方便医生诊断"
- 无在线医生：提示"当前无在线医生，预计等待XX分钟，是否继续排队？"
- 提交失败：提示"提交失败，请检查网络后重试"

---

#### 步骤3：医生接诊（预计5-15分钟）
**医生端操作**：
1. 医生收到问诊请求推送通知
2. 医生查看问诊信息：
   - 患者基本信息（脱敏处理）
   - 症状描述、发病时间
   - 既往病史、用药史
   - 患者上传的图片资料
3. 医生点击"开始接诊"
4. 系统建立即时通讯连接（腾讯IM）
5. 医生与患者进行在线沟通：
   - 医生询问详细病情
   - 患者回答医生问题
   - 必要时医生要求补充资料
6. 医生根据问诊情况做出判断：
   - 需要开处方 -> 进入开方流程
   - 建议线下就医 -> 结束问诊并给出建议
   - 无需用药 -> 结束问诊并给出健康建议

**患者端体验**：
1. 患者提交问诊后进入等待页面
2. 页面显示：
   - 当前排队位置（如：前面还有X人）
   - 预计等待时间
   - 医生信息预览（如已匹配）
3. 患者收到医生接诊通知
4. 进入问诊会话界面
5. 患者与医生进行文字/图片沟通

**系统处理**：
- 建立医患之间的IM连接
- 记录整个问诊过程的聊天记录
- 实时同步双方的输入状态
- 计时（问诊时长限制）
- 保存问诊记录到数据库

**异常处理**：
- 医生超时未接诊：自动转派其他医生或提醒医生
- IM连接失败：自动重连，提示用户网络问题
- 医生断线：提示患者等待医生重连
- 患者断线：保存会话状态，患者重连后可继续

---

#### 步骤4：医生开方（预计3-5分钟）
**医生端操作**：
1. 医生根据问诊情况判断需要开处方
2. 点击"开具处方"按钮，进入开方界面
3. 填写处方信息：
   - 诊断结果：主要诊断、次要诊断（ICD-10编码）
   - 药品信息：
     - 药品名称（从药品库选择或手动输入）
     - 规格、剂量
     - 用法用量（每日几次、每次多少）
     - 用药天数
     - 药品数量
   - 可添加多个药品
4. 填写医嘱说明：
   - 用药注意事项
   - 复诊建议
   - 生活建议
5. 系统自动校验处方：
   - 药品配伍禁忌检查
   - 剂量合理性检查
   - 患者过敏史冲突检查
   - 药品与既往用药冲突检查
6. 校验通过后，医生电子签名确认
7. 点击"提交处方"

**系统处理**：
- 生成唯一处方编号（遵循国家处方编码规范）
- 记录处方详细信息到数据库
- 执行处方审核规则引擎
- 保存医生电子签名和时间戳
- 更新问诊记录状态为"已开方"
- 推送处方信息给患者端

**患者端体验**：
1. 患者收到"医生已开处方"通知
2. 点击通知查看处方详情
3. 页面显示：
   - 诊断结果
   - 开具药品列表（名称、规格、用法用量）
   - 医嘱说明
   - 药品总价
   - "去购药"按钮

**异常处理**：
- 处方校验失败：提示医生具体错误信息（如"该药品与患者过敏史冲突"）
- 药品库存不足：提示医生更换药品或调整数量
- 处方签名失败：提示医生重新签名
- 患者拒绝处方：提供"重新问诊"或"取消订单"选项

---

#### 步骤5：患者支付（预计2-3分钟）
**用户操作**：
1. 患者查看处方详情后，点击"去购药"按钮
2. 系统跳转至订单确认页面
3. 患者确认订单信息：
   - 药品信息：名称、规格、数量、单价、小计
   - 处方信息：处方编号、医生姓名、诊断结果
   - 收货地址：选择或添加新地址
   - 配送方式：
     - 快递配送（显示预计送达时间、运费）
     - 到店自取（显示门店地址、营业时间）
   - 优惠券：选择可用优惠券
   - 发票信息：选择是否开具发票
4. 查看订单金额明细：
   - 商品总金额
   - 运费
   - 优惠金额
   - 应付总额
5. 点击"提交订单"
6. 进入支付页面，选择支付方式：
   - 微信支付
   - 支付宝
   - 医保支付（如可用）
   - 余额支付
7. 完成支付

**系统处理**：
- 验证处方有效性（未过期、未使用）
- 计算订单金额（药品价格、运费、优惠）
- 检查库存并锁定
- 生成唯一订单号
- 创建订单记录（状态：待支付）
- 调用支付接口
- 支付成功后：
  - 更新订单状态为"已支付、待发货"
  - 更新处方状态为"已使用"
  - 扣减库存
  - 发送支付成功通知
  - 通知商家发货

**异常处理**：
- 处方已过期：提示"处方已过期，请重新问诊开方"
- 处方已被使用：提示"该处方已使用，请勿重复购药"
- 库存不足：提示"部分药品库存不足，建议更换门店或等待补货"
- 支付超时：订单自动取消，库存释放，提示"支付超时，订单已取消，请重新下单"
- 支付失败：提示具体失败原因

## 2. 在线购药流程（问诊购药）

### 2.1 流程概览

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ AI预问诊 │ -> │ 智能推荐 │ -> │ 选择路径 │ -> │ 问诊开方 │ -> │ 购药支付 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

### 2.2 详细步骤说明

#### 步骤1：AI预问诊（预计2-3分钟）
**用户操作**：
1. 用户进入"问诊购药"入口
2. 系统显示AI预问诊界面
3. 用户选择就诊人
4. AI助手引导用户描述症状：
   - "请问您哪里不舒服？"
   - 用户可输入文字描述或语音输入
5. AI进一步询问细节：
   - 症状持续时间
   - 症状严重程度
   - 伴随症状
   - 既往病史
   - 过敏史
6. 用户回答AI的问题
7. AI总结用户的症状信息

**系统处理**：
- 启动AI预问诊对话引擎
- 分析用户输入的自然语言
- 提取关键症状信息
- 构建用户症状画像
- 评估症状紧急程度
- 生成预问诊报告

**AI预问诊输出**：
- 症状摘要
- 可能涉及的疾病方向
- 推荐就诊科室
- 建议就诊紧急程度（普通/紧急）

**异常处理**：
- 用户描述不清：AI主动追问具体细节
- 症状严重预警：提示"您的症状可能需要紧急就医，建议立即前往医院"
- AI无法识别症状：提示"建议您选择具体科室进行问诊"

---

#### 步骤2：智能推荐（预计1分钟）
**用户操作**：
1. AI预问诊完成后，系统显示智能推荐页面
2. 页面显示：
   - 症状分析结果
   - 推荐就诊科室（多个可选）
   - 推荐医生列表
   - 可能需要的检查项目
   - 健康科普知识
3. 用户可选择：
   - 直接选择推荐的医生进行问诊
   - 查看更多医生
   - 选择其他科室
   - 查看药品推荐

**系统处理**：
- 基于AI预问诊结果进行智能分析
- 匹配最适合的科室和医生
- 查询在线医生状态
- 计算医生匹配度评分
- 生成个性化推荐列表
- 预测可能需要的服务

**推荐算法考虑因素**：
- 医生专业领域与症状的匹配度
- 医生在线状态和接诊量
- 患者历史就诊记录
- 医生评价和好评率
- 问诊价格区间

**异常处理**：
- 无在线医生：提示"当前该科室无在线医生，建议选择其他科室或预约离线医生"
- 推荐不准确：提供"重新选择科室"入口

---

#### 步骤3：选择问诊路径（预计1分钟）
**用户操作**：
1. 系统展示可选的问诊路径：

   **路径A：快速问诊（推荐）**
   - 系统自动分配医生
   - 平均等待时间3-5分钟
   - 适合常见病症
   - 价格：XX元起

   **路径B：专家问诊**
   - 自主选择医生
   - 可查看医生详细介绍
   - 适合复杂病症
   - 价格：根据医生定价

   **路径C：团队问诊**
   - 多学科医生会诊
   - 适合疑难杂症
   - 价格：较高

2. 用户选择适合的问诊路径
3. 系统根据选择进入相应流程

**系统处理**：
- 分析用户画像和症状复杂度
- 推荐最适合的问诊路径
- 显示各路径的详细信息
- 记录用户选择偏好

**路径差异化处理**：
| 特性 | 快速问诊 | 专家问诊 | 团队问诊 |
|------|----------|----------|----------|
| 医生分配 | 自动分配 | 用户自选 | 系统组织 |
| 等待时间 | 3-5分钟 | 依医生而定 | 预约制 |
| 问诊时长 | 15分钟 | 30分钟 | 60分钟 |
| 复诊优惠 | 7天内免费 | 依医生政策 | 含后续咨询 |
| 适用症状 | 常见轻症 | 专科疾病 | 复杂疑难 |

**异常处理**：
- 快速问诊排队过长：建议转专家问诊或预约
- 专家医生离线：提示"预约该医生"选项
- 症状不适合线上问诊：提示"建议您前往医院面诊"

---

#### 步骤4-6：问诊开方与购药支付

选择好问诊路径后，后续流程与"在线处方购药流程"的步骤3-5相同：
- **步骤4**：医生接诊（详见1.2.3）
- **步骤5**：医生开方（详见1.2.4）
- **步骤6**：患者支付（详见1.2.5）

**差异化说明**：
1. 快速问诊可能直接进入开方环节（如复诊）
2. 专家问诊可能涉及更详细的沟通和建议
3. 团队问诊可能需要异步会诊，耗时较长

## 3. 到店购药流程

### 3.1 流程概览

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 选购药品 │ -> │ 问诊开方 │ -> │ 选择门店 │ -> │ 支付订单 │ -> │ 到店取药 │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

### 3.2 详细步骤说明

#### 步骤1：选购药品（同在线流程）
与在线处方购药流程的步骤1一致。

---

#### 步骤2：问诊开方（同在线流程）

与在线处方购药流程的步骤2-4一致。

---

#### 步骤3：选择门店（预计1-3分钟）
**用户操作**：
1. 医生开方后，系统跳转至门店选择页面
2. 页面显示地图和门店列表：
   - 默认显示用户当前位置附近门店
   - 地图标注各门店位置
   - 列表显示门店详细信息
3. 门店信息包括：
   - 门店名称、地址、距离
   - 营业时间、联系电话
   - 药品库存状态
   - 预计取药时间
   - 用户评价
4. 用户可通过以下方式筛选门店：
   - 按距离排序（最近优先）
   - 按库存排序（有库存优先）
   - 按评分排序
   - 按营业时间（24小时营业）
5. 用户选择目标门店
6. 系统显示该门店的详细信息
7. 用户确认选择，点击"确认门店"

**系统处理**：
- 获取用户当前地理位置
- 查询附近所有合作门店
- 检查各门店药品库存
- 计算用户与门店距离
- 评估各门店预计取药时间
- 排序并展示门店列表
- 记录用户选择偏好

**智能推荐逻辑**：
- 优先推荐有完整库存的门店
- 优先推荐距离最近的门店
- 考虑门店当前排队情况
- 考虑用户历史选择偏好

**异常处理**：
- 附近无合作门店：提示"您所在地区暂未开通到店取药服务，建议选择快递配送"
- 所有门店均无库存：提示"当前门店库存不足，建议选择快递配送或等待补货"
- 定位失败：提示"无法获取您的位置，请手动输入地址或选择区域"
- 门店休息：提示"该门店当前休息，建议选择其他门店或预约取药"

---

#### 步骤4：支付订单（预计2-3分钟）
**用户操作**：
1. 确认门店后，系统跳转至订单确认页面
2. 用户确认订单信息：
   - 药品信息（名称、规格、数量、单价）
   - 处方信息（处方编号、医生姓名）
   - 取药门店信息（名称、地址、联系电话）
   - 预计取药时间
   - 取药人信息（默认为就诊人，可修改）
   - 优惠券选择
3. 查看订单金额明细：
   - 商品总金额
   - 优惠金额
   - 应付总额
4. 点击"提交订单"
5. 进入支付页面，选择支付方式：
   - 微信支付
   - 支付宝
   - 医保支付（如可用）
   - 余额支付
6. 完成支付

**系统处理**：
- 验证处方有效性
- 锁定门店药品库存
- 生成取药订单（区别于配送订单）
- 生成唯一取药码（二维码/数字码）
- 计算订单金额
- 处理支付请求
- 支付成功后：
  - 更新订单状态为"待取药"
  - 更新处方状态为"已使用"
  - 扣减门店库存
  - 生成取药码
  - 发送支付成功和取药通知

**取药码生成规则**：
- 二维码：包含订单ID、取药码、门店信息、有效期
- 数字码：8位随机数字（如：8X4K9P2M）
- 有效期：支付成功后24小时

**异常处理**：
- 处方已过期：提示"处方已过期，请重新问诊开方"
- 门店库存不足：提示"该门店库存不足，请选择其他门店"
- 支付超时：订单取消，库存释放，提示"支付超时，订单已取消"
- 支付失败：提示具体失败原因

---

#### 步骤5：到店取药（预计5-10分钟）
**用户操作**：
1. 用户在订单页面查看取药码
2. 前往所选门店
3. 到达门店后：
   - 向店员出示取药码（二维码或数字码）
   - 或告知店员订单号和取药码
4. 店员核验取药码
5. 店员根据订单信息配药
6. 用户核对药品：
   - 药品名称、规格
   - 药品数量
   - 药品有效期
7. 确认无误后，用户在电子签收单上签字确认
8. 店员完成出库操作
9. 用户取走药品

**店员端操作**：
1. 登录门店管理系统
2. 扫描或输入顾客提供的取药码
3. 系统显示订单详情：
   - 订单号、取药码
   - 药品清单
   - 顾客信息（脱敏）
   - 处方信息
4. 核验取药码有效性：
   - 检查是否已过期
   - 检查是否已使用
5. 根据药品清单配药
6. 扫描药品条码确认药品正确
7. 向顾客展示药品，确认无误
8. 请顾客在电子屏签字确认
9. 点击"确认出库"
10. 打印取药凭证（可选）

**系统处理**：
- 验证取药码有效性和时效性
- 查询订单详情
- 记录取药操作日志
- 更新订单状态为"已完成"
- 更新库存数据（实际出库）
- 保存电子签收记录
- 触发售后保障计时（如7天无理由退换）
- 发送取药成功通知

**订单状态流转**：
```
待支付 -> 待取药 -> 已完成
           |
           已取消（超时未取药）
```

**取药码使用规则**：
- 一次性有效，使用后立即失效
- 有效期24小时（从支付成功开始计算）
- 支持二维码扫描和数字码输入两种方式
- 超过有效期自动失效，订单变为"已取消"

**异常处理**：
- 取药码无效：提示"取药码错误或已失效，请检查或联系客服"
- 取药码过期：提示"取药码已过期，订单已自动取消，如需购药请重新下单"
- 药品缺货：店员操作"部分缺货"，系统计算退款金额，用户确认后退款
- 用户拒收：记录原因，订单取消，药品退回库存，启动退款流程

## 4. 关键业务逻辑详细说明

### 4.1 智能分单逻辑

#### 4.1.1 分单场景

智能分单主要应用于以下场景：
1. 在线购药选择配送方式时
2. 订单分配给具体门店时
3. 问诊分配给医生时
4. 取药订单分配到门店

#### 4.1.2 分单目标

- 用户体验最优：最快送达、最少等待
- 成本最优：最低配送成本、最高库存周转
- 商家利益最大化：订单分配均衡、避免忙闲不均
- 服务质量：匹配最合适的医生和服务资源

#### 4.1.3 分单算法

**多因素评分模型**：
```
总分 = w1×距离分 + w2×库存分 + w3×时效分 + w4×质量分 + w5×成本分

其中：
- w1, w2, w3, w4, w5 为权重系数，可根据业务策略调整
- 各维度分数标准化为0-100分
```

**维度详解**：
| 维度 | 计算方式 | 说明 |
|------|----------|------|
| 距离分 | 100 - (实际距离/最大服务距离)×100 | 距离越近分数越高 |
| 库存分 | (实际库存/需求数量)×100，超过100计100 | 库存充足分数高 |
| 时效分 | 根据历史配送/处理时间计算 | 处理速度越快分数越高 |
| 质量分 | 用户评价、投诉率、退货率综合计算 | 服务质量越好分数越高 |
| 成本分 | 根据配送成本、运营成本计算 | 成本越低分数越高 |

**权重配置策略**：
| 场景 | 距离权重 | 时效权重 | 质量权重 | 说明 |
|------|----------|----------|----------|------|
| 急用药 | 40% | 40% | 10% | 快速送达优先 |
| 普通购药 | 30% | 20% | 30% | 均衡考虑 |
| 慢病用药 | 20% | 10% | 40% | 服务质量优先 |
| 夜间购药 | 50% | 30% | 10% | 就近优先 |

**负载均衡策略**：
为了避免订单集中在少数优质门店/医生，引入负载均衡机制：

```
负载系数 = 当前待处理订单数 / 平均处理能力

修正分数 = 原始分数 / (1 + 负载系数)
```

**动态调整机制**：
系统实时监控分单效果，动态调整：
1. 高峰期增加时效权重
2. 恶劣天气增加距离权重
3. 新门店增加质量权重以积累评价
4. 投诉率高的门店降低质量分

#### 4.1.4 分单流程

```
开始分单
    |
收集候选列表（门店/医生）
    |
排除不可用选项（休息/离线/满负荷）
    |
对选项计算各项维度分数
    |
应用权重计算总分
    |
应用负载均衡修正
    |
按总分排序
    |
选择TOP3候选
    |
返回分单结果
    |
结束
```

#### 4.1.5 特殊场景处理

**场景1：紧急用药需求**
- 识别关键词："急用"、"马上"、"现在"
- 策略：距离权重提升至50%，优先选择3公里内门店
- 如附近无可用门店，主动推荐其他紧急购药渠道

**场景2：慢病续方**
- 识别：历史订单中有慢病药品
- 策略：优先分配原开方医生
- 简化问诊流程，快速续方

**场景3：夜间购药**
- 识别：22:00-08:00时段
- 策略：仅显示24小时营业门店
- 增加夜间配送费说明

**场景4：多件商品**
- 策略：检查单门店是否满足全部库存
- 如不能，计算拆分订单 vs 寻找全库存门店的最优解

### 4.2 就诊人管理逻辑

#### 4.2.1 就诊人概念定义
就诊人是指实际需要接受医疗服务或购买处方药的人员。一个用户账号可以管理多个就诊人（如家庭成员）。

#### 4.2.2 就诊人信息结构
| 信息类别 | 字段 | 必填 | 说明 |
|----------|------|------|------|
| 基本信息 | 姓名 | 是 | 真实姓名 |
| | 性别 | 是 | 男/女 |
| | 出生日期 | 是 | 用于计算年龄 |
| | 身份证号 | 是 | 实名认证用 |
| 联系信息 | 手机号 | 是 | 联系方式 |
| | 地址 | 是 | 配送地址 |
| 健康信息 | 身高 | 否 | 用于计算BMI |
| | 体重 | 否 | 用药剂量参考 |
| | 血型 | 否 | 急救参考 |
| | 过敏史 | 是 | 用药安全 |
| | 既往病史 | 否 | 慢性病、手术史 |
| | 用药史 | 否 | 长期用药记录 |
| 档案信息 | 医保卡号 | 否 | 医保支付用 |
| | 就诊卡号 | 否 | 合作医院用 |

#### 4.2.3 就诊人管理流程
**流程1：添加就诊人**

```
用户发起添加就诊人
    |
选择添加方式
  ├─ 方式1：手动输入
  │    |
  │    填写就诊人信息表单
  │    |
  │    身份证OCR识别（可选）
  │    |
  │    验证手机号（短信验证码）
  │    |
  │    完成添加
  │
  └─ 方式2：从家人列表导入
       |
       授权获取家人信息
       |
       选择要导入的家人
       |
       确认导入
       |
       完成添加
    |
保存就诊人信息
    |
返回就诊人列表
```

**流程2：编辑就诊人信息**

```
用户选择就诊人
    |
进入就诊人详情页
    |
点击"编辑"
    |
修改需要更新的字段
    |
验证变更（如手机号变更需验证）
    |
保存修改
    |
更新就诊人信息
```

**流程3：删除就诊人**

```
用户选择就诊人
    |
进入就诊人详情页
    |
点击"删除"
    |
系统检查是否存在：
  ├─ 进行中的订单？-> 提示"存在进行中的订单，无法删除"
  ├─ 未完成的问诊？-> 提示"存在未完成的问诊，无法删除"
  ├─ 有效的处方？-> 提示"存在有效处方，删除后处方将失效，是否继续？"
  └─ 无关联数据 -> 直接删除
    |
确认删除
    |
标记就诊人为"已删除"
    |
从列表中移除
```

**流程4：切换就诊人**

```

    |
系统默认选择上次使用的就诊人
    |
用户可点击切换就诊人
    |
弹出就诊人选择列表
    |
显示该用户下的所有就诊人
    |
用户选择目标就诊人
    |
系统验证就诊人信息完整性
    |
验证通过 -> 切换成功
验证不通过 -> 提示完善信息
```

#### 4.2.4 就诊人权限管理
**角色权限矩阵**：
| 操作 | 本人 | 家庭成员 | 其他 |
|------|------|----------|------|
| 查看基本信息 | 是 | 是 | 否 |
| 查看健康档案 | 是 | 是（授权） | 否 |
| 编辑信息 | 是 | 部分（授权） | 否 |
| 删除 | 是 | 否 | 否 |
| 代问诊 | 是 | 是 | 否 |
| 代购药 | 是 | 是 | 否 |

**授权机制**：
- 就诊人可授权其他用户（如子女）管理自己的信息
- 授权可设置有效期和操作范围
- 可随时撤销授权
- 所有授权操作需短信验证

#### 4.2.5 就诊人数据安全
**数据保护措施**：
1. **敏感信息加密**：身份证号、手机号等加密存储
2. **访问控制**：严格的权限验证
3. **操作审计**：记录所有访问和修改日志
4. **数据脱敏**：对外展示时隐藏敏感信息
5. **定期清理**：删除长期未使用的就诊人数据

**隐私保护**：
- 未经用户授权，不向第三方披露就诊人信息
- 医疗数据不出境
- 遵循《个人信息保护法》和《数据安全法》

### 4.3 处方生命周期管理

#### 4.3.1 处方状态定义
| 状态 | 说明 | 可转移状态 |
|------|------|------------|
| 待生效 | 处方已开具，医生尚未确认 | 已生效、已作废 |
| 已生效 | 处方正式生效，可用于购药 | 已使用、已过期 |
| 已使用 | 处方已被用于购药 | - |
| 已过期 | 超过有效期（默认3天） | - |
| 已作废 | 医生主动作废 | - |
| 已退款 | 使用后订单退款 | - |

#### 4.3.2 处方状态流转图

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 待生效  │ -> │ 已生效  │ -> │ 已使用  │   │ 已过期  │
└─────────┘   └─────────┘   └─────────┘   └─────────┘
      │              │
      │              └────────────────────────┐
      │                                       │
      └───────────────────────────────────────┘
                  │
            ┌─────────┐
            │ 已作废  │
            └─────────┘
```

#### 4.3.3 处方有效期管理
**有效期规则**：
- 普通处方：开具后3天内有效
- 急诊处方：开具后1天内有效
- 慢性病处方：开具后7天内有效
- 特殊药品处方：按法规要求执行

**有效期提醒**：
- 处方生效后48小时：提示"处方将在2天后过期"
- 处方生效后72小时：提示"处方将在1天后过期，请尽快使用"
- 处方过期前12小时：提示"处方即将过期，请尽快使用或重新问诊"

#### 4.3.4 处方使用规则

**使用限制**：
1. 一张处方只能使用一次
2. 处方必须在有效期内使用
3. 处方药品必须一次性购齐（不可分批）
4. 处方药品数量不得超过处方规定数量

**使用流程**：
1. 用户选择使用处方购药
2. 系统验证处方有效性
3. 系统锁定处方（防止并发使用）
4. 用户完成支付
5. 系统标记处方为"已使用"
6. 处方失效，不能再用于购药

#### 4.3.5 处方异常处理

**处方丢失**：
- 用户可在"我的处方"中查看所有历史处方
- 支持通过就诊人、时间、药品等条件筛选
- 电子处方永久保存，可随时查看

**处方纠错**：
- 医生发现处方有误，可在未使用前作废重开
- 患者发现处方问题，可联系医生协商处理
- 已使用的处方不支持修改

**处方争议**：
- 因处方问题导致的纠纷，由平台介入调查
- 根据问诊记录和处方内容判定责任
- 涉及医生执业问题，上报卫生主管部门
