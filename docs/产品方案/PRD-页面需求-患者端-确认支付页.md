## 1. 页面概述

### 1.1 页面定位

确认支付页是订单流程中的关键环节，承接订单确认页提交后的支付确认环节。用户在完成订单信息确认后，进入本页面选择支付方式并完成付款操作，实现订单支付闭环。

### 1.2 业务目标

| 目标类型 | 具体目标 | 衡量指标 |
|----------|----------|----------|
| 业务目标 | 提升支付转化率 | 支付完成率 ≥ 95% |
| 用户体验 | 简化支付流程 | 平均支付时长 ≤ 60秒 |
| 安全合规 | 保障支付安全 | 支付纠纷率 ≤ 0.1% |
| 医保推广 | 提升医保支付占比 | 医保支付订单占比 ≥ 30% |

### 1.3 用户场景

**场景一：普通药品微信支付**
- 用户：张先生，35岁，购买感冒药
- 场景：提交订单后进入支付页，选择微信支付，扫码完成付款
- 期望：支付流程简单快捷

**场景二：处方药医保支付**
- 用户：李女士，58岁，购买慢性病药物
- 场景：使用电子处方购药，选择医保支付，首次使用需授权医保
- 期望：医保支付流程清晰，授权引导明确

**场景三：混合支付场景**
- 用户：王先生，65岁，购买高价特效药
- 场景：订单金额500元，医保个人账户余额300元，需现金支付200元
- 期望：混合支付明细清晰，扣款逻辑透明

#### 2.2.5 混合支付明细

**混合支付触发条件：**
- 订单类型为医保订单
- 用户选择医保支付
- 医保个人账户余额 < 订单金额

**混合支付明细展示：**
```
┌────────────────────────────────────────┐
│ 支付明细                               │
├────────────────────────────────────────┤
│ 医保个人账户支付    ¥ 1,250.80         │
│ (可用余额)                             │
├────────────────────────────────────────┤
│ 现金支付           ¥   249.20          │
│ (微信支付)                             │
├────────────────────────────────────────┤
│ 订单总金额        ¥ 1,500.00           │
└────────────────────────────────────────┘
```

**混合支付计算逻辑：**
```
订单总金额 = 药品金额 + 运费 - 优惠金额

医保支付金额 = MIN(医保个人账户余额, 订单总金额)

现金支付金额 = 订单总金额 - 医保支付金额

注：若医保支付金额 = 订单总金额，则无需现金支付
```

```typescript
interface PaymentInfoResponse {
  code: number;
  message: string;
  data: {
    // 订单基本信息
    orderId: string;                    // 订单号
    orderType: number;                  // 订单类型：1-普通 2-处方 3-医保
    orderStatus: number;                // 订单状态
    merchantName: string;               // 商家名称
    merchantId: string;                 // 商家ID
    
    // 金额信息
    totalAmount: number;                // 订单总金额
    goodsAmount: number;                // 商品金额
    freightAmount: number;              // 运费
    discountAmount: number;             // 优惠金额
    
    // 商品信息
    itemCount: number;                  // 商品件数
    mainProductName: string;             // 主商品名称
    
    // 支付信息
    expireTime: string;                 // 订单过期时间
    remainingSeconds: number;            // 剩余秒数
    
    // 支付方式
    availableMethods: PaymentMethod[]; // 可用支付方式列表
    
    // 医保信息（医保订单时返回）
    medicalInsurance?: MedicalInsuranceInfo;
  }
}

interface PaymentMethod {
  methodCode: string;                   // 支付方式代码：wechat/alipay/mi
  methodName: string;                   // 支付方式名称
  icon: string;                         // 图标URL
  isDefault: boolean;                   // 是否默认选中
  isRecommended: boolean;               // 是否推荐
  needAuth: boolean;                    // 是否需要授权
  disabled: boolean;                    // 是否禁用
  disabledReason?: string;             // 禁用原因

interface MedicalInsuranceInfo {
  isEligible: boolean;                  // 是否符合医保支付条件
  ineligibleReason?: string;             // 不符合原因
  isAuthorized: boolean;                 // 是否已授权
  authExpireTime?: string;               // 授权过期时间
  balance: number;                      // 医保个人账户余额

  settlementEstimate?: {
    totalAmount: number;                // 总金额
```

#### 6.1.4 发起支付

**接口地址**: `POST /api/v1/payments`

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| orderId | String | 是 | 订单ID |
| paymentMethod | String | 是 | 支付方式：wechat/alipay/mi/mix |
| miAuthCode | String | 否 | 医保授权码（医保支付时必填） |
| mixPayment | Object | 否 | 混合支付信息（混合支付时必填） |

**mixPayment结构**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| miAmount | Number | 是 | 医保支付金额 |
| cashAmount | Number | 是 | 现金支付金额 |
| cashMethod | String | 是 | 现金支付方式：wechat/alipay |

**响应数据**:

```typescript
interface PaymentCreateResponse {
  code: number;
  message: string;
  data: {
    paymentId: string;                  // 支付单号
    paymentStatus: number;                // 支付状态：0-待支付 1-支付中 2-成功 3-失败
    
    // 微信支付参数（微信支付时返回）
    wechatPayParams?: {
      appId: string;
      timeStamp: string;
      nonceStr: string;
      package: string;
      signType: string;
      paySign: string;
    }
    
    // 支付宝支付参数（支付宝支付时返回）
    alipayParams?: {
      orderInfo: string;
    }
    
    // 医保支付参数（医保支付时返回）
    miPayParams?: {
      settlementNo: string;
      poolingPayment: number;
      personalPayment: number;
      selfPayment: number;
    }
    
    // 混合支付参数（混合支付时返回）
    mixPayParams?: {
      miAmount: number;
      cashParams: WechatPayParams | AlipayParams;
    }
  }
}
```

```typescript
  }
```

| 支付结果查询间隔 | 2s | 3s | 轮询查询支付状态 |
| 支付结果返回时间 | ≤ 5s | ≤ 10s | 支付成功到结果返回 |
| 页面流畅度 | 60fps | 45fps | 页面滚动和动画帧率 |

### 9.2 优化策略

## 10. 安全需求

### 10.1 安全要求

| 安全项 | 要求 | 实现方式 |
|--------|------|----------|
| 数据传输安全 | 全链路HTTPS | TLS 1.2+加密传输 |
| 敏感信息加密 | 前端不保存敏感信息 | 卡号、密码等不上传前端 |
| 支付请求签名 | 请求参数防篡改 | HMAC-SHA256签名 |
| 防重放攻击 | 请求时效性验证 | 时间戳+随机数校验 |
| 支付结果验证 | 多渠道结果校验 | 服务端主动查询确认 |
| 接口权限控制 | 敏感接口权限验证 | JWT Token + 权限校验 |
| 异常监控告警 | 异常支付行为监控 | 实时风控规则检查 |

### 10.2 风控策略

| 风控场景 | 触发条件 | 处理策略 |
|----------|----------|----------|
| 高频支付 | 1小时内支付 > 10次 | 短信验证 + 人工审核 |
| 大额支付 | 单笔 > 5000元 | 人脸识别验证 |
| 异地支付 | 登录地与支付地距离 > 500km | 短信验证 |
| 夜间支付 | 00:00-06:00支付 | 增加验证环节 |
| 新设备支付 | 首次在新设备支付 | 短信验证 |
| 失败重试 | 连续失败 > 3次 | 锁定支付功能15分钟 |
