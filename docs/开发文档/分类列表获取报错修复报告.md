# 分类列表获取报错修复报告

## 问题描述
访问商城端分类页面时，获取分类列表API报错，导致页面无法正常显示药品数据。

## 根本原因

### MySQL保留字冲突
`Drug`实体类中的`usage`字段是MySQL的**保留关键字**，在SQL查询中如果没有用反引号（`）包裹，会导致SQL语法错误。

### 错误日志
```
java.sql.SQLSyntaxErrorException: You have an error in your SQL syntax; 
check the manual that corresponds to your MySQL server version for the right syntax to use near 'usage,description,status,sort_order,create_time,update_time,is_deleted FROM dm_p' at line 1

SQL: SELECT id,product_code,product_name,category_id,brand_id,main_image,images,specification,unit,manufacturer,approval_number,price,original_price,stock,warning_stock,sales,is_rx,usage,description,status,sort_order,create_time,update_time,is_deleted FROM dm_product WHERE id=? AND is_deleted=0
```

### 影响范围
- ❌ 所有涉及`dm_product`表的查询都会失败
- ❌ 药品详情接口 `/v1/drugs/{id}` 无法工作
- ❌ 药品列表接口 `/v1/drugs` 无法工作
- ❌ 分类页面无法获取药品数据
- ❌ 后端服务崩溃退出

## 解决方案

### 修复代码

**文件**: `backend/src/main/java/com/drugmall/entity/Drug.java`

```java
// 修复前
private String usage;

// 修复后
@TableField("`usage`")
private String usage;
```

### 修复说明
使用MyBatis-Plus的`@TableField`注解，将字段名用反引号包裹，这样生成的SQL会是：
```sql
SELECT ..., `usage`, ... FROM dm_product
```

而不是：
```sql
SELECT ..., usage, ... FROM dm_product  -- ❌ 语法错误
```

## MySQL常见保留字

以下字段名在MySQL中是保留字，需要特别处理：

| 字段名 | 风险等级 | 建议处理方式 |
|--------|---------|-------------|
| `usage` | ⚠️ 高 | 必须用反引号或改名 |
| `order` | ⚠️ 高 | 必须用反引号或改名 |
| `group` | ⚠️ 高 | 必须用反引号或改名 |
| `select` | ⚠️ 高 | 必须用反引号或改名 |
| `index` | ⚠️ 中 | 建议用反引号 |
| `key` | ⚠️ 中 | 建议用反引号 |
| `status` | ✅ 低 | 通常安全 |
| `name` | ✅ 低 | 通常安全 |

### 最佳实践

1. **避免使用保留字作为字段名**
   - `usage` → `drug_usage` 或 `usage_method`
   - `order` → `sort_order` 或 `display_order`

2. **如果必须使用，添加@TableField注解**
   ```java
   @TableField("`usage`")
   private String usage;
   ```

3. **数据库设计规范**
   - 使用有意义的业务前缀
   - 避免单单词段名
   - 统一命名规范（如全部小写+下划线）

## 其他发现的问题

### 1. 端口占用问题
**现象**: 启动时报错 "Port 8080 was already in use"

**解决**:
```powershell
# 停止所有Java进程
Get-Process -Name "java" | Stop-Process -Force

# 或者只停止特定端口的进程
Get-NetTCPConnection -LocalPort 8080 | Select-Object -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }
```

### 2. 字符编码问题
**现象**: 日志中中文显示为乱码（如`鑽搧`）

**原因**: 控制台编码不是UTF-8

**影响**: 仅影响日志可读性，不影响功能

**建议**: 
- 设置IDEA控制台编码为UTF-8
- 或在application.yml中配置日志编码
