### 2. 数据流程分析

#### ✅ 患者端发起问诊流程（正常）

1. 患者在问诊页面选择医生
2. 填写症状描述
3. 点击"发起问诊"
4. 前端调用 `POST /api/v1/patient/consultations`
5. 后端 `PatientConsultationController.createConsultation()` 调用Service
6. `ConsultationServiceImpl.createConsultation()` 保存到数据库
7. 返回问诊VO给前端
8. 患者端显示"等待接诊"页面

**验证结果**：✅ 数据已成功插入数据库，状态为`pending`

#### ✅ 医生端获取问诊列表流程（正常）

1. 医生访问问诊管理页面
2. 页面 `onMounted` 调用 `consultationStore.fetchConsultations()`
3. Store调用 `getDoctorConsultations('all')` API
4. 前端请求 `GET /api/v1/consultations?status=all`
5. 后端 `ConsultationController.listConsultations()` 查询数据库
6. 查询条件：`WHERE doctor_id = 'DOC001'`
7. 返回问诊列表VO

**验证结果**：✅ API接口配置正确，数据库有数据

## 🎯 问题根因

### 可能原因1：医生端页面未刷新

如果医生在患者发起问诊**之前**就已经打开了问诊管理页面，页面只会加载一次数据。

**解决方案**：
- 刷新医生端页面（F5或Ctrl+R）
- 或切换到其他标签页再切回来

### 可能原因2：数据转换问题

前端API定义的类型 `DoctorConsult` 与后端返回的 `ConsultationVO` 字段可能不完全匹配。

**需要检查**：
1. 后端 `ConsultationVO` 的字段
2. 前端 `DoctorConsultation` 接口的字段
3. 字段映射是否一致

### 可能原因3：患者信息缺失

问诊记录中有 `patient_id`，但显示时需要 `patientName`、`patientAge`、`patientGender` 等字段。如果Service层没有关联查询患者表，这些字段可能为空。
