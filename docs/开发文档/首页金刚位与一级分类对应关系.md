# 首页金刚位与一级分类对应关系

**日期**: 2026-04-28  
**状态**: ✅ 已完成

---

## 📋 需求说明

首页推荐页的金刚位（服务网格）点击后，应该跳转到对应的分类页面，并显示该一级分类下的二级、三级分类和商品。

---

## 🔗 跳转流程

### 1. 首页金刚位点击

**文件**: `frontend/src/views/home/components/ServiceGridSection.vue`

```typescript
function handleServiceClick(item: ServiceItemData) {
  router.push(`/category?active=${item.id}`)
}
```

**示例**:
- 点击"感冒发烧" → `/category?active=1`
- 点击"医疗器械" → `/category?active=2`
- 点击"保健品" → `/category?active=3`

### 2. 分类页接收参数

**文件**: `frontend/src/views/category/index.vue`

```typescript
// 从URL参数获取一级分类ID（支持id和active两种参数名）
const categoryId = (route.query.id || route.query.active) as string
if (categoryId) {
  activeLevel1Id.value = categoryId
  
  // 自动选中第一个二级分类
  if (level2Categories.value.length > 0) {
    activeLevel2Id.value = level2Categories.value[0].id
    
    // 自动选中第一个三级分类
    const level3Subs = allCategories.value.filter(c => c.parentId === activeLevel2Id.value)
    if (level3Subs.length > 0) {
      activeLevel3Id.value = level3Subs[0].id
    }
  }
}
```

**兼容性**: 
- ✅ 支持 `?id=X` 参数（直接访问）
- ✅ 支持 `?active=X` 参数（从首页跳转）

## ⚠️ 当前问题

### 问题描述

首页金刚位的`item.id`是硬编码的字符串（'1', '2', '3'...），但这些ID与数据库中一级分类的实际ID不对应：

**首页金刚位数据** (`ServiceGridSection.vue`):
```typescript
const services = ref<ServiceItemData[]>([
  { id: '1', name: '感冒发烧', ... },
  { id: '2', name: '咳嗽化痰', ... },
  { id: '3', name: '肠胃用药', ... },
  ...
  { id: '10', name: '医疗器械', ... },
  ...
  { id: '18', name: '滋补养生', ... },
])
```

**数据库一级分类**:
```sql
ID: 1 - 药品
ID: 2 - 医疗器械
ID: 3 - 保健品
```

### 影响

当用户点击首页金刚位时：
- 点击"感冒发烧" (id='1') → 跳转到 `/category?active=1` → 显示"药品"分类 ✅
- 点击"医疗器械" (id='10') → 跳转到 `/category?active=10` → **找不到ID=10的一级分类** ❌
- 点击"滋补养生" (id='18') → 跳转到 `/category?active=18` → **找不到ID=18的一级分类** ❌

---

## 💡 解决方案

### 方案1：修改首页金刚位数据（推荐）

将首页金刚位的`item.id`改为与数据库一级分类ID对应：

```typescript
const services = ref<ServiceItemData[]>([
  // 药品相关
  { id: '1', name: '感冒发烧', category: '药品', ... },
  { id: '1', name: '咳嗽化痰', category: '药品', ... },
  { id: '1', name: '肠胃用药', category: '药品', ... },
  
  // 医疗器械
  { id: '2', name: '医疗器械', category: '医疗器械', ... },
  
  // 保健品
  { id: '3', name: '滋补养生', category: '保健品', ... },
])
```

**优点**: 
- 简单直接
- 不需要修改后端
- 保持数据一致性

**缺点**:
- 需要手动维护映射关系

### 方案2：动态加载一级分类（最佳）

从后端API动态加载一级分类数据作为金刚位：

```typescript
import { getDrugCategories } from '@/api/modules/drug'

const services = ref<ServiceItemData[]>([])

onMounted(async () => {
  const categories = await getDrugCategories()
  // 筛选出一级分类（parentId为null）
  const level1Categories = categories.filter(c => !c.parentId)
  
  services.value = level1Categories.map(cat => ({
    id: cat.id,
    name: cat.name,
    iconUrl: getCategoryIcon(cat.name), // 根据分类名称匹配图标
    bgColor: getCategoryColor(cat.name), // 根据分类名称匹配背景色
    category: cat.name
  }))
})
```

**优点**:
- 完全动态化
- 数据源统一
- 易于维护

**缺点**:
- 需要修改首页组件（您要求不修改）
- 需要为每个分类配置图标和颜色

### 方案3：建立映射表（折中方案）

在分类页或单独的配置文件中建立映射关系：

```typescript
// 金刚位ID到一级分类ID的映射
const kingkongToCategoryMap: Record<string, string> = {
  '1': '1',   // 感冒发烧 -> 药品
  '2': '1',   // 咳嗽化痰 -> 药品
  '3': '1',   // 肠胃用药 -> 药品
  '4': '1',   // 皮肤用药 -> 药品
  '5': '1',   // 维生素钙 -> 药品
  '6': '1',   // 止痛消炎 -> 药品
  '7': '1',   // 五官用药 -> 药品
  '8': '1',   // 儿童用药 -> 药品
  '9': '1',   // 慢病用药 -> 药品
  '10': '2',  // 医疗器械 -> 医疗器械
  '11': '1',  // 中药饮片 -> 药品
  '12': '1',  // 男科用药 -> 药品
  '13': '1',  // 妇科用药 -> 药品
  '14': '1',  // 避孕测孕 -> 药品
  '15': '1',  // 过敏用药 -> 药品
  '16': '1',  // 肝胆用药 -> 药品
  '17': '1',  // 心脑血管 -> 药品
  '18': '3',  // 滋补养生 -> 保健品
  '19': '1',  // 口腔护理 -> 药品
  '20': '1',  // 眼科用药 -> 药品
}
```

然后在分类页使用映射：

```typescript
const categoryId = route.query.active as string
const mappedCategoryId = kingkongToCategoryMap[categoryId] || categoryId
if (mappedCategoryId) {
  activeLevel1Id.value = mappedCategoryId
  // ... 后续逻辑
}
```

**优点**:
- 不修改首页组件
- 灵活性高
- 易于调整

**缺点**:
- 需要维护映射表
- 增加了一层转换
